# AI stateful V1 application schema — P0 contract

Status: schema contract, NOT applied migration. Database `ai_db` belongs to
root `ai-service`; ecommerce V1/Flyway/DBML are not its migration source.
P2 implements async SQLAlchemy/Alembic migration and pinned saver bootstrap.
All identifiers are UUIDs generated by the application. Timestamps are timestamptz
UTC; revisions/sequence/generation use non-negative/positive bigint checks.
No FK to another service's account table: account_id is verified JWT identity.

## conversations

| Column | Type / rule |
| --- | --- |
| id | uuid PK; stable LangGraph root thread_id equals id |
| account_id | uuid NOT NULL, immutable owner |
| title | varchar(200) NULL |
| revision | bigint NOT NULL DEFAULT 0, CHECK >= 0 |
| accepted_checkpoint_id | text NULL; nonblank if present |
| active_run_id | uuid NULL; execution slot, not inferred from run status |
| created_at, updated_at | timestamptz NOT NULL |

CHECK `(revision = 0) = (accepted_checkpoint_id IS NULL)`. Namespace is the empty
root namespace; thread identity derives from id, never latest. Native saver refs
are opaque values: no SQL FK into framework internals or manual checkpoint writes.
Index `(account_id, updated_at DESC, id DESC)` for owner lists.

## agent_runs

| Column | Type / rule |
| --- | --- |
| id | uuid PK; UNIQUE(conversation_id, id) for scoped refs |
| conversation_id | uuid NOT NULL FK conversations.id ON DELETE CASCADE |
| request_id | uuid NOT NULL; UNIQUE(conversation_id, request_id) |
| request_hash | varchar(64) NOT NULL, lowercase SHA-256 shape CHECK |
| request_payload | jsonb NOT NULL object; validated TurnRequestV1 |
| kind | varchar NOT NULL CHECK CHAT/DEBUG/REPLAY |
| status | varchar NOT NULL, enum values from RunStatus |
| base_revision | bigint NOT NULL CHECK >= 0 |
| base_checkpoint_ref, last_checkpoint_ref, final_checkpoint_ref | jsonb NULL, internal CheckpointRefV1 objects |
| authorized_recovery_source_refs | jsonb NOT NULL DEFAULT '[]', array |
| execution_id, worker_instance_id | uuid NULL until claim |
| lease_generation | bigint NOT NULL DEFAULT 0 CHECK >= 0 |
| lease_expires_at, heartbeat_at | timestamptz NULL; not stop evidence |
| cancel_requested | boolean NOT NULL DEFAULT false |
| executor_stop_evidence | jsonb NULL, trusted verified ExecutionStopEvidenceV1 |
| attempt_count, max_attempts | int NOT NULL CHECK attempt_count >= 0, max_attempts > 0 |
| retry_policy_version | text NOT NULL, finite policy supplied by application |
| retry_deadline | timestamptz NOT NULL |
| versions, error | jsonb NULL; versioned validated internal payloads |
| trace_id | text NULL, no secrets/prompts in diagnostic labels |
| replay_snapshot | jsonb NULL, validated ReplaySnapshotV1 |
| created_at, updated_at | timestamptz NOT NULL |
| started_at, finished_at | timestamptz NULL |

Index `(conversation_id, created_at, id)` and `(status, lease_expires_at)`.
Active slot composite FK `(conversations.id, active_run_id)` references
`agent_runs(conversation_id,id)` and is deferred for transaction ordering; clear
it only after verified exact-attempt stop evidence. No partial index by RUNNING
status is sufficient for thread admission. Generation fences application publish,
not framework put(). DEBUG/REPLAY kind must be rejected by customer publication
and not modify accepted checkpoint/revision, regardless of status.

## conversation_messages

| Column | Type / rule |
| --- | --- |
| id | uuid PK |
| conversation_id | uuid NOT NULL FK conversations.id ON DELETE CASCADE |
| run_id | uuid NOT NULL; composite FK(conversation_id,run_id) to agent_runs |
| sequence | bigint NOT NULL CHECK > 0; UNIQUE(conversation_id,sequence) |
| role | varchar NOT NULL CHECK user/assistant |
| content | text NOT NULL, nonblank |
| payload | jsonb NULL, validated public result/build only |
| created_at | timestamptz NOT NULL |

UNIQUE(run_id,role): one submitted user message and at most one published assistant
message per run. Messages are appended transactionally; assistant message, run
finalization, accepted ref and revision move in one fenced CAS transaction.
Retry/resume never inserts another user/assistant message for the same run.
Message append order comes from the serialized conversation transaction, not
timestamps or MAX(sequence) read outside its lock/CAS boundary.

## Framework data and stream events

Native checkpointer tables/indexes are owned by pinned AsyncPostgresSaver.setup().
Do not recreate them in Alembic or assume current framework table names/schema.
Application conversation deletion must explicitly purge saver data for the
stable thread after execution stop/drain; application cascades cannot reach it.
P2 native gate verifies refs/lineage/reopen before selecting the durable adapter.

P5 adds a persisted run-event journal for reconnect, scoped `(run_id,sequence)`
uniqueness, retention and deletion. It must not overload checkpoint pending writes
or user message history. This delivery table is not required for P2's three-table
foundation; its migration is part of P5 acceptance, not an already existing table.

Retention: chat/runs/checkpoints 90 days; true orphan/debug checkpoints 7 days.
P2/P4 cleanup must preserve accepted/recoverable lineage until parent conversation
expires, and stop/drain active writes before purge. User deletion removes every
related application/framework/event/snapshot record. Internal-only replay cannot
publish. Cleanup clock/attempt defaults and batch-size configuration are adapter
details to document and verify in P2/P4; no expiration job is claimed here.
