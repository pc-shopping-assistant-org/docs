# AI persistence reference

Database `ai_db` belongs to root `ai-service`; ecommerce Flyway/DBML are not its
migration source. Application SQLAlchemy/Alembic and native LangGraph saver have
separate ownership. Concepts: [state/recovery](../04-ai/context-management.md).
Setup: [First steps](../04-ai/getting-started.md). Verification: [status](../04-ai/stateful-implementation-status.md).
Current head is `0005_event_payload`; historical migrations are not edited. Startup requires
this exact application release revision and reads tables without creating them.
DBML: `ai-stateful.dbml`; generated constraint reference: `ai-stateful-constraints.sql`.
Apply via `alembic upgrade head`, then `python -m ai_service.bootstrap_stateful`.
All identifiers are UUIDs generated by the application. Timestamps are timestamptz
UTC; revisions/sequence/generation use non-negative/positive bigint checks.
No FK to another service's account table: account_id is verified JWT identity.

## agent_run_events (0004/0005)

`id uuid PK`, `conversation_id/run_id uuid`, `sequence bigint >0`,
`dedup_key varchar(200) nonblank`, `event_type START|DELTA|COMPLETED|ERROR`,
`payload jsonb` typed public envelope, `created_at timestamptz`.
Unique `(run_id, sequence)` and `(run_id, dedup_key)`; compound FK to
`agent_runs(conversation_id,id)` with CASCADE. Append locks run before allocating
sequence; same key/payload returns original event, changed payload rejects.
Envelope identity/type/sequence matches row; missing JSON fields reject via
COALESCE(false). Event inserts share caller transaction, so rollback emits nothing.
Cursor is persisted event UUID scoped to owned run. No FK into LangGraph tables.
Journal/lifecycle emission and basic HTTP SSE are implemented; public reconnect
is outside selected scope. V2 completion payload retains public
flexible state. Event-write failure rolls back assistant/head/event changes together.

## conversations

| Column | Type / rule |
| --- | --- |
| id | uuid PK; stable LangGraph root thread_id equals id |
| account_id | uuid NOT NULL, immutable owner |
| title | varchar(200) NULL |
| revision | bigint NOT NULL DEFAULT 0, CHECK >= 0 |
| accepted_checkpoint_id | text NULL; nonblank if present |
| active_run_id | uuid NULL; execution slot, not inferred from run status |
| created_at, updated_at | timestamptz NOT NULL |

CHECK `revision = 0 OR accepted_checkpoint_id IS NOT NULL`. Revision zero may have
an accepted initial root. Public readiness derives from the accepted ref:
NULL → INITIALIZING, present → READY. Creation locks the owned conversation row,
awaits native root persistence, then CAS attaches the exact ref without increasing
revision. Existing populated rows are not automatically migrated. Namespace is the empty
root namespace; thread identity derives from id, never latest. Native saver refs
are opaque values: no SQL FK into framework internals or manual checkpoint writes.
Index `(account_id, updated_at DESC, id DESC)` for owner lists.

## agent_runs

| Column | Type / rule |
| --- | --- |
| id | uuid PK; UNIQUE(conversation_id, id) for scoped refs |
| conversation_id | uuid NOT NULL FK conversations.id ON DELETE CASCADE |
| request_id | uuid NOT NULL; UNIQUE(conversation_id, request_id) |
| request_hash | varchar(64) NOT NULL, lowercase SHA-256 shape CHECK |
| request_payload | jsonb NOT NULL object; validated selected TurnRequestV1/V2 |
| kind | varchar NOT NULL CHECK CHAT/DEBUG/REPLAY |
| status | varchar NOT NULL, enum values from RunStatus |
| base_revision | bigint NOT NULL CHECK >= 0 |
| base_checkpoint_ref, last_checkpoint_ref, final_checkpoint_ref | jsonb NULL, internal CheckpointRefV1 objects |
| authorized_recovery_source_refs | jsonb NOT NULL DEFAULT '[]', array |
| execution_id, worker_instance_id | uuid NULL until claim |
| lease_generation | bigint NOT NULL DEFAULT 0 CHECK >= 0 |
| lease_expires_at, heartbeat_at | timestamptz NULL; not stop evidence |
| cancel_requested | boolean NOT NULL DEFAULT false |
| executor_stop_evidence | jsonb NULL, trusted verified ExecutionStopEvidenceV1 |
| attempt_count, max_attempts | int NOT NULL CHECK attempt_count >= 0, max_attempts > 0 |
| retry_policy_version | text NOT NULL, finite policy supplied by application |
| retry_deadline | timestamptz NOT NULL |
| versions, error | jsonb NULL; versioned validated internal payloads |
| trace_id | text NULL, no secrets/prompts in diagnostic labels |
| replay_snapshot | jsonb NULL, validated ReplaySnapshotV1 |
| created_at, updated_at | timestamptz NOT NULL |
| started_at, finished_at | timestamptz NULL |

Index `(conversation_id, created_at, id)` and `(status, lease_expires_at)`.
Active slot composite FK `(conversations.id, active_run_id)` references
`agent_runs(conversation_id,id)` and is deferred for transaction ordering; clear
it only after verified exact-attempt stop evidence. No partial index by RUNNING
status is sufficient for thread admission. Generation fences application publish,
not framework put(). DEBUG/REPLAY kind must be rejected by customer publication
and not modify accepted checkpoint/revision, regardless of status.

## conversation_messages

| Column | Type / rule |
| --- | --- |
| id | uuid PK |
| conversation_id | uuid NOT NULL FK conversations.id ON DELETE CASCADE |
| run_id | uuid NOT NULL; composite FK(conversation_id,run_id) to agent_runs |
| sequence | bigint NOT NULL CHECK > 0; UNIQUE(conversation_id,sequence) |
| role | varchar NOT NULL CHECK user/assistant |
| content | text NOT NULL, nonblank |
| payload | jsonb NULL, validated public result/build only |
| created_at | timestamptz NOT NULL |

UNIQUE(run_id,role): one submitted user message and at most one published assistant
message per run. Messages are appended transactionally; assistant message, run
finalization, accepted ref and revision move in one fenced CAS transaction.
Retry/resume never inserts another user/assistant message for the same run.
Message append order comes from the serialized conversation transaction, not
timestamps or MAX(sequence) read outside its lock/CAS boundary.

## Framework data and stream events

### External attempt accounting — Alembic 0002

`agent_call_budgets`: run_id PK/FK to agent_runs ON DELETE CASCADE; explicit
non-negative model_limit/tool_io_limit and durable timestamptz deadline. No budget
row means dispatch is forbidden, not unlimited. No policy limits are invented by
the migration. Submit/coordinator must insert the approved per-run limits.

`agent_call_attempts`: id PK, run_id FK to budget ON DELETE CASCADE; execution_id,
worker_instance_id, positive generation; kind MODEL/TOOL_IO; nonblank operation_key
(200 chars), lowercase SHA-256 request_hash, positive attempt_number. Unique
(run_id, operation_key, attempt_number), index (run_id,kind). Status is
RESERVED/SUCCEEDED/FAILED/UNKNOWN; finished_at is NULL exactly while RESERVED.
Reservation locks conversation then run, checks active slot/current execution,
lease/cancellation/deadline and counts **all statuses**, commits before dispatch.
Crash/timeout reservations remain counted; only exact DB-stored trusted stop
evidence permits settling them UNKNOWN. This settlement neither grants takeover
nor frees the thread. New generation/reopen does not reset caps. No raw prompts,
credentials or duplicate tool results are stored here.

AttemptBoundary and PostgreSQL ledger are implemented. Provider/backend adapters
must disable or instrument hidden retries for attempt-cap accounting. Usage and
provider request metadata are deliberately not recorded yet; UNKNOWN is never a
zero-cost claim. This is not a provider billing cap or exactly-once guarantee.

Native checkpointer tables/indexes are owned by pinned AsyncPostgresSaver.setup().
Do not recreate them in Alembic or assume current framework table names/schema.
Application conversation deletion must explicitly purge saver data for the
stable thread after execution stop/drain; application cascades cannot reach it.
P2 native gate verifies refs/lineage/reopen before selecting the durable adapter.

Run-event journal is the existing application delivery table with scoped sequence/
dedup uniqueness. It does not overload native pending writes or message history.
Public reconnect is not enabled; retention/delete remain unimplemented jobs.

Retention: chat/runs/checkpoints 90 days; true orphan/debug checkpoints 7 days.
P2/P4 cleanup must preserve accepted/recoverable lineage until parent conversation
expires, and stop/drain active writes before purge. User deletion removes every
related application/framework/event/snapshot record. Internal-only replay cannot
publish. Cleanup clock/attempt defaults and batch-size configuration are adapter
details to document and verify in P2/P4; no expiration job is claimed here.

## Optimizer provenance snapshot contract

OptimizerExecutionSnapshotV1 được lưu immutable cùng completion checkpoint;
không chỉ lưu hash hoặc selected SKU. Payload bắt buộc:

Đây là application DTO versioned, extra="forbid"; identity dùng UUID và revision
integer non-negative, timestamps UTC, monetary fields integer VND non-negative.
Normalized input tái sử dụng typed ComponentSpec/PCBuildConstraints đã validate,
không dùng dict[str, Any] làm contract optimizer. Policy maps dùng typed enum
profile/objective và finite numeric values; serialized ordering/hash được chốt
bằng golden fixtures. P0 DTO có trong provenance.py; core stage capture đã có một phần source/tests.
Complete persisted snapshot/artifacts và replay adapter vẫn cần native/runtime gates.

| Field | Nội dung |
| --- | --- |
| identity | schema_version=1, conversation_id, run_id, base_revision, constraints_revision |
| constraints_snapshot | Merged values + source/lock/evidence, resolved owned/pinned, explicit budget scope/units, requested objective |
| catalog_snapshot | Canonical rows/fields dùng resolve/normalize: variant/SKU, visibility/stock/price, attributes/benchmark evidence, retrieved_at, backend revision nếu backend cung cấp |
| normalized_input | Toàn bộ ordered normalized candidates/ComponentSpec và effective spending mapping thực sự đưa vào optimizer; không chỉ final parts |
| synthetic_sources | iGPU/stock-cooler identity/kind, parent variant/evidence; không tạo commerce SKU giả |
| versions | graph/state/DTO, normalization/compatibility/optimizer/pruning/scoring/recommendation versions, engine code commit/artifact digest, Python/dependency lock digest |
| policy_snapshot | Resolved weights/tables/thresholds, tie-break/order rules, search limits/config, config hash, seed nếu có randomness |
| hashes | catalog_snapshot_hash, normalized_input_hash, optimization_input_hash, optimization_result_hash, recommendation_result_hash |
| results | Typed optimization outcome/result, recommendation decision/score breakdown/evidence; INFEASIBLE tách khỏi successful build |

Snapshot đủ để chạy optimizer offline mà không lấy catalog/policy hiện tại.
Nếu dùng immutable blob ref thay inline JSON, ref kèm digest và được giữ cùng
retention/lineage; missing blob/hash mismatch làm replay fail rõ ràng. Trước mắt
ưu tiên inline validated payload có size limit, không thêm storage platform.

Hash format V1: SHA-256 của application-canonical UTF-8 JSON: sorted object keys,
compact separators, enum/UUID thành string, UTC timestamps, finite numbers;
reject NaN/Infinity. Giữ array order nếu ảnh hưởng optimizer; set-like collections
normalize/sort trước hash. Có hash-format version và golden serialization tests.
optimization_input_hash bao gồm actual normalized input và effective algorithm/
policy config; audit run ID/retrieval timestamp đứng riêng, không đổi semantic
input hash chỉ vì được ghi nhận ở lượt khác. Snapshot/result hashes kiểm tra
integrity; không thay thế payload và versions/config thực tế.

Explanation provenance lưu trong checkpoint: input hash, prompt template/version,
provider/model/config, evidence/result refs, validated output và output hash.
Không lưu secrets/chain-of-thought. Text cũ đọc từ output đã lưu; LLM replay có
thể khác câu chữ. Chỉ claim optimizer reproducibility sau replay test đúng code/
config/environment. New build vẫn revalidate live visibility/stock/price; snapshot
lịch sử không trở thành dữ liệu catalog hiện tại.
